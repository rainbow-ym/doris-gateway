# 浏览器接入操作说明

版本：2026.10.13-onboarding.1。现有测试服务地址 http://192.168.232.132:18080 ，MySQL 网关端口 3308。

## 使用流程

1. 在“数据源与接入”保存 Doris FE 地址、9030 端口、真实数据库用户名和密码、库表匹配范围。保存新连接时会测试账号。
2. 点击“发现数据库”。只列出该账号可见且匹配范围的库，默认选择未接入的库；可以取消不需要的项。
3. 点击“接入选中数据库”。每个库显示排队、执行阶段、完成或失败原因；刷新页面不会中断任务。已完成的库不会重复创建。
4. 在“字段策略”复核自动推荐的证件号、姓名等规则，批量调整后到“变更发布”预览并发布。推荐只根据字段名、注释，不保证识别所有敏感字段，必须复核。
5. 业务系统使用原数据源用户名、原密码和同名数据库连接网关地址 192.168.232.132:3308。SQL 无需添加参数。敏感字段仍可用于明文匹配，返回按策略处理。

例如连接真实 Doris 的 test 账号选择 DWH_入口，网关也生成 test 账号，并授权访问 DWH_入口。Storage Unit 是内部生成的存储标识，不再手填。原 gateway_test 仅是旧测试账号，平台不再用它初始化业务库。

## 匹配范围与账号约束

- 匹配采用 SQL LIKE：`%` 表示任意字符串，`_` 表示单个字符；精确下划线可用 `\_`。`DWH_%` 不等于 `DWD_%`。
- 一个网关实例内用户名必须唯一。同名数据库账号需要使用相同密码，否则拒绝保存，避免认证歧义。
- 同名逻辑数据库不能同时映射到两个不同连接。遇到冲突应使用原连接，或先解除旧映射。
- 平台独立控制账号必须 `admin: true`，只供后台使用。业务账号不是 Proxy 管理员，不能执行 DistSQL（包括导出配置）；普通 SHOW 与 information_schema 不做过滤。
- 初次安装仍需设置服务端口、平台账号、主密钥及控制账号等基础启动配置。库表映射与字段规则通过平台维护，不要求业务 YAML。

## 编辑、删除与失败恢复

- 编辑连接密码留空表示不变。已有映射的连接可以改名称和发现范围；改变服务器、账号或密码须先解除相关映射。
- 删除没有接入依赖的连接不会删除 Doris 数据。已有映射时先“解除接入”，其对应业务访问立即失效，再删除连接。
- 历史重复记录保留，避免误删关联配置；按编号识别并删除不需要的无依赖连接。新连接禁止重名及相同账号、地址、范围的重复保存。
- “失败”不表示可以忽略。先看执行阶段与指引，修复地址、权限或范围后点击“重试接入”。外部创建的对象在“运行与血缘”批准纳管，失败同步可点击“重试同步”。
- 物理数据库必须已存在且账号可见；平台不会替用户创建缺失的业务数据库，也不会把找不到的库标记成功。
- 如果提示已有其他存储单元，不自动覆盖：核实旧映射后解除并重新接入。

## 发布与运维

使用普通 `docker run` 脚本，无 Compose，支持测试服务器 Docker 1.13。管理数据库、网关仓库和密钥保存在宿主机挂载目录，重建容器不清空这些目录。

现有服务器配置：`/data/doris-security-gateway/gateway.env`、`/data/doris-security-gateway-admin/admin.env`。发布前备份这些文件及数据库目录。不要在运行时直接复制 H2 文件充当一致性备份，应停管理服务后复制。

生产须使用 HTTPS 保护管理登录，只开放管理网；限制 Proxy 控制账号与数据库文件访问。不要更换已用于加密连接密码的 ADMIN_MASTER_KEY_B64。网关 DDL 和管理数据库不是跨系统原子事务；同步未完成时拒绝访问，失败依靠执行记录恢复，并非承诺任意语句零失败、零延迟。
