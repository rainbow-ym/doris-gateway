# 可编辑 CSV 与紧凑逐行密文（ROW_V3）

## 开启方式

升级后原配置不变。在 SM4 加密导出列表点击“编辑”，填写“不可修改的记录标识列”，
例如查询结果中的 `record_id`，保存后重新查询、导出。留空继续生成旧 ROW_V2 文件。
记录标识必须是查询返回的准确列名/别名、未脱敏、非空，并且在本次结果中唯一。
不会自动挑选主键，也不额外读取业务字段；查询缺少标识或编号重复时整个查询失败。
同一账号配置此模式后，所有命中加密保护的查询都需要包含该标识列。

## 文件编辑规则

新文件允许普通列新增、删除、改名、改值和调整顺序；解密输出沿用上传文件的列顺序，
只恢复受保护字段。新增备注、修改后的普通内容不代表网关认证的原始业务事实。
受保护列和记录标识可移动位置，但不得改名、删除、改值。
所有表头必须唯一且非空；保留最后的 `__gateway_sm4` 列，其名称、位置和密文内容不能修改。
可整行排序或取部分行，密文要跟随对应记录；禁止重复密文行、混合不同查询批次。
字符、空格、数字格式必须保真，Excel 自动改写记录编号或脱敏值将导致校验失败。
仍只支持带表头的 UTF-8 CSV，文件大小 1 MiB、业务列最多 255、数据行最多 1000；
查询配置的行数上限和原有缓冲/密文大小限制不变。

每行的认证密文绑定批次、行号、保护原值，以及保护字段/记录编号的完整性摘要。
替换另一行密文，即使两行脱敏值相同，也因记录编号不同而被拒绝。
如果用户整行复制，包括编号和受保护内容一起移动，这就是同一业务记录的移动，
不是系统能够推断的“人为改变业务含义”；普通内容允许编辑，因此不能认证其真实性。

## 密文长度和存储

每行只携带格式版本、批次编号、批内行号、原值和不可修改部分的摘要。
账号、列定义、来源身份、过期时间等公共元数据以 SM4-GCM 认证加密后在 Worker 管理库保存一次。
原值、脱敏行内容和完整行密文不持久化到该管理库。密钥仍在原密钥文件中。
一次新格式查询保存一条加密记录、一份公共元数据、一条加密审计；
一次新格式文件解密成功写一条审计，失败写拒绝审计。
测试样例由 693 字符缩短至 225 字符；这不是所有查询的固定长度。
原值更长、敏感字段更多仍会产生更长密文；没有削弱认证标签或截断密文。

新格式必须保留对应 Worker 的元数据、账号、原密钥和授权。
只复制密钥到另一套空数据库不能解密。备份时要一起备份 Worker 数据目录和密钥。
页面显示撤销范围：ROW_V3 按整个查询批次撤销，所有行和副本均失去解密资格；
ROW_V2 保持原来的按行撤销语义。改变记录标识配置不会改变旧文件内部的列定义。

## 清理策略

- 每 60 秒最多清理 10000 条已过期解密记录；关联的新格式元数据级联清理。
  大量历史积压会分批处理，过期时立即拒绝解密，不依赖清理任务是否已运行。
- 历史审计默认不删除。Worker 环境变量 `SM4_EXPORT_AUDIT_RETENTION_DAYS`
  为 0 时保留；设为 1—3650 时，按该天数清理查询加密/解密/解密拒绝审计，每轮最多 10000 条。
  不清理配置变更、撤销等其他审计。启用清理前应确定组织的审计保留要求。
- `SM4_EXPORT_CLEANUP_MS` 可调整扫描间隔，默认 60000 毫秒，必须为正值。
- 不删除密钥、账号、业务数据或有效期内的解密记录。
  默认保留的审计仍会增长，只是新格式已从每行一条降为每次查询一条。

环境变量要在容器创建时注入；只修改 ENV 再 restart 不生效。
首次升级会添加兼容字段、批次表和过期索引；开启审计清理时会添加审计索引。
已有记录很多时首次建索引可能较慢，应在维护窗口进行，保留冷备。

## 兼容与回退

旧 ROW_V2 文件仍按原完整列/内容规则解密，不能事后变成可编辑文件，需重新导出。
版本识别使用认证后的密文内容，保留现有密文列名和外层前缀，无需业务系统换接口。
已下载的新格式文件需要新版 Worker；旧 Worker 不理解 ROW_V3。
一键升级仍支持开放业务前回退；开放业务后不能盲目恢复旧库，以免丢失批次元数据。
本轮没有修改按库自动授权、有效期最大天数、查询行数上限或 JVM 资源配置。
