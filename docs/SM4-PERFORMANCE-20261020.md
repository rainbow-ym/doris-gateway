# SM4 查询性能第一阶段

## 本轮范围

基于 main a2289fba64093a5877d6b940deb3f479087b4a8c，保持 ROW_V2 密文兼容、原有权限检查和大小限制。
目标是 5 个不同 Doris 账号同时执行受保护查询；并发数不是 QPS，实际吞吐量须在生产数据上测量。

- 每批查询只读取一次配置、解析一次账号、读取一次密钥；不跨请求缓存权限或密钥。
- 每批对每个来源逻辑库/表核对一次物理身份，同表多列复用检查结果。
- 逐行独立随机 nonce、认证密文、撤销记录和审计仍保留，记录批量写入原事务。
- 完成全部加密及大小校验后才写入记录；失败不返回部分结果。
- Worker 加密许可覆盖整个批次；默认并发上限 8。Proxy 默认也为 8。
- 加密接口独立读取超时默认 60 秒，其他控制接口保留原设置；通信错误与加密超时分开提示。

没有增加每行连接线程池。5 个请求可由服务器线程并行完成各自的计算；先消除重复 I/O，
不把 96 核转换成 96 个同时向 Doris 建连的线程。无需为每个小结果申请大量堆内存。

## 配置

| 所在容器 | 环境变量 | 默认 | 含义 |
|---|---|---|---|
| Worker 和 Proxy | SM4_EXPORT_MAX_CONCURRENT | 8 | 各实例加密并发许可，1—64；两侧建议一致 |
| Proxy | SM4_EXPORT_TIMEOUT_MS | 60000 | 等待加密接口响应的毫秒数 |

默认值已覆盖本轮 5 并发目标，不需要修改 worker.ENV。自定义环境变量必须在容器创建时注入，
只修改 ENV 文件再 restart 不会更新已创建容器的环境。此包不会擅自改变原 JVM 堆、Docker 内存/CPU 限制。
96 核、100G 可用内存不等于容器已获得这些资源；上线前检查容器限制及 JVM 参数。
若现场发生 GC/内存压力再评估 Worker 2—4G 堆、Proxy 4—8G 堆，保留现有其他 JVM 参数。
行数默认 200、最大 1000，以及缓冲/密文/CSV 大小上限保持原样；不能承诺任意 180 行宽表都符合大小限制。

## 验证边界

自动化覆盖 5 个不同账号同时各加密 180 行（共 900 行），逐条验证原值、用户名和账号版本；
来源身份提供器在测试中模拟，使用真实 SM4-GCM 和 H2 写入。此测试不能代表生产 Doris QPS。
同时覆盖来源去重、不跨查询缓存、201 行超限、批次失败、原有解密权限/篡改/撤销校验，
以及加密专用超时和明确的超时错误。

现场先对同一 SQL 分别测 20、180、200 行，再运行 5 个不同账号同时查询，记录每次延迟、
成功率、CPU/GC、Worker 和 Doris 连接数。QPS = 成功查询数 / 测试持续秒数。
SQL 排序/数据量、来源表数、字段宽度、网络和磁盘都会影响延迟，不给未实测的 QPS 保证。

3. 上传前调整列顺序、选择列、增加备注的安全映射设计，保留行密文和防错还原。
4. 待本轮真实性能数据确认后再扩大结果规模或增加批内计算线程。
