# 第二批：查询生效快照与策略发布日志

范围：仅开发和 132 隔离实例验证，未更新正式 3308 / 18080 服务，未替换用户安装包。

后续自动发布隔离进展见 [第三批记录](整改进度-20261016-自动发布隔离.md)。本文边界清单保留第二批结束时状态。

## 本批实现

1. 新增 `policy_publications` 保存不可变候选、发布前快照及发布状态；`active_policy_snapshots` 保存各逻辑库的生效版本指针及完整快照。
2. 发布先持久化 APPLYING，再执行 Proxy 规则变更并读回校验，最后在一个 H2 本地事务中切换生效快照和版本状态。发布与回滚按逻辑库串行化，大小写输入归一化。
3. 多用户模式查询计划读取生效快照中的字段类型和已解析算法参数，不再读取草稿作为全局返回策略，也不依赖正在 DROP/CREATE 的 Proxy MASK 规则。每次结果集构造期间获取快照、预编译列算法，返回过程中不重新读取。
4. 失败尝试恢复原 Proxy 规则，再读回验证；恢复成功记 FAILED，不能验证恢复记 RECOVERY_REQUIRED。旧生效快照不会因发布失败被删除。
5. 重启后保留 APPLYING / RECOVERY_REQUIRED，拒绝用新的发布覆盖未核实任务；不把同名对象存在或进程重启视作发布成功。
6. 回滚通过同一套发布和校验流程切换到指定版本发布前的快照。**回滚不覆盖当前草稿**，避免破坏管理员未发布的编辑；页面确认及返回消息明确说明。后续再次发布会使用当前草稿。
7. 无生效快照的逻辑库拒绝生成返回计划，必须先显式发布并验证。首次发布以及旧历史记录没有可验证前置快照，禁止回滚到未经确认的空规则。
8. 发布记录 ID 改为获取本次 INSERT 的生成键，去掉并发不安全的 MAX(id)。

## 测试

- admin：65 项，64 通过，1 跳过；proxy：46 项，22 通过，24 跳过。合计实际执行 86 项通过，25 项跳过。
- 新增单元测试覆盖：草稿隔离、完整版本切换、发布失败恢复、恢复失败阻断、未完成日志跨重启保留、首次/旧版拒绝回滚、切换事务失败不移动指针、回滚失败保留当前版本、大小写归一化、40 次并发插入版本归属，以及 Proxy 使用快照算法/拒绝旧协议。
- 132 隔离 worker 18086 / Proxy 3312：新增 4 组快照测试通过，包含连续 4 次发布与 30 次查询并发；原保护边界 6 组、多用户 13 组、账号生命周期 6 组通过。
- 保护边界测试预期更新：手动删除目标 Proxy MASK 规则时，查询仍按持久化快照脱敏，而不是依赖缺规则报错。
- worker 实际重启后，在不重新发布的情况下，服务端预编译查询继续按原快照脱敏，验证通过。
- 测试仅操作合成测试库 `gateway_multi_acceptance_20261014` 和隔离管理数据副本。不改变 Doris 全局或库默认副本数。

## 边界与后续工作

- 本批只切断**多用户查询返回策略**对草稿和可变 Proxy 规则的依赖，不是整个控制面的完全版本化。血缘继承和自动纳管仍可能读取草稿、触发全库发布；需继续拆分“管理员草稿”与“自动继承变更”，避免自动建表发布夹带未发布编辑。
- 尚无 APPLYING / RECOVERY_REQUIRED 的人工核实恢复界面或一键恢复工具；当前安全行为是阻止覆盖发布并保留旧快照。这是故障安全措施，不是完整可用性恢复闭环。
- 旧安装升级必须安排明确的快照初始化步骤；不能直接滚动替换 Proxy 或 worker，不能将新版 Proxy 与旧版策略接口混用。正式升级/回滚脚本尚未提供，因此本批不发布。
- 锁只覆盖单 worker 进程；未支持同一系统库多个 worker 并发发布。每集群独立实例模式保持不变。
- 生效快照没有对象代次和 schema 版本校验。DDL 与查询并发的全周期一致性、跨库同一发布世代、显式事务提交绑定仍属后续阶段，不能声称已解决。
- 用户例外策略仍在保存后生效，并在单次查询中固定；本批版本/回滚范围是全局返回策略，不包括用户例外规则的历史版本。
- 非多用户旧运行模式仍走原 Proxy MASK 流程，不获得此快照保证。
- 仍保留 H2；新增两张表自动建表，无外部数据库迁移。实际数据备份、快照历史清理、密钥轮换待后续处理。
