# 执行结果与审计确认边界

2026-10-17，北京时间。沿用现有架构，处理自查 F13 的错误分类与关联信息，不宣称完整解决 F10/F11/F13。

## 本批修改

- 多用户 StandardDatabaseProxyConnector 每次执行生成一个 UUID 请求编号，执行前 STARTED 与执行链返回后的 EXECUTED 使用相同编号。
- 执行前审计必须得到成功响应，否则不调用业务执行。即使旧配置 `GATEWAY_LINEAGE_FAIL_CLOSED=false`，此审计路径也不静默放行。
- 执行链返回成功、但结束审计写入失败：返回 SQLSTATE `HY000`、错误码 `39001`，提示“完成审计未确认、不要自动重试业务 SQL”，附请求编号；不记录成数据库执行失败，不重新执行业务 SQL。
- SQL 成功回调中的血缘/保护同步异常标记为执行后确认失败；在多用户执行入口转换为上述待核实错误，而不是暗示原业务没有执行。
- 执行链抛异常时审计记为 UNKNOWN。普通权限/语法错误仍保留原异常，不把客户端错误文本一律替换；UNKNOWN 是保守的管线状态，并不表示每次错误都真的发生了写入。
- 不确定异常识别增加 JDBC nextException 链、HYT00/HYT01/40003、SQLRecoverableException，兼容 cause 环并避免无限遍历；abort 使用相同判定，避免将这类失败当成明确回滚而开放对象。
- 审计只附请求编号、用户、库、SQL 摘要，不新增 SQL 原文或查询结果。接口保留旧版不传 requestId 的兼容性。

## 验证

Java 单元测试：admin 89 项（88 通过、1 跳过），Proxy 58 项（34 通过、24 跳过）；实际执行共 122 项通过，25 项跳过。

新增 6 项执行确认测试：前置审计失败不执行、后置失败只执行一次、成功关联同一编号、同步失败不重放、普通错误与附加审计失败处理、嵌套超时与循环异常链。

另有 1 项真实 HTTP 故障测试：子 JVM 使用测试 HTTP 服务，STARTED 返回 200、EXECUTED 返回 503；即使设置旧 fail-open 参数也必须返回 39001，模拟业务调用次数为 1。这不是 Doris 真实写入后的断网注入测试。

132 隔离实例真实验证：

- 查询仍脱敏，审计两条记录使用相同请求编号且不含原始 SQL/结果。
- 事务边界 3 组、保护边界 6 组、多用户 13 组全部通过。
- 通过隔离 stage、只读查询验收及 accept 启动新配套镜像。未改正式服务。

## 仍然存在的限制

1. 没有实现 durable outbox 或后台审计补投。若结束审计未写入，已持久化的 STARTED 记录仍保留，需要人工凭请求编号核实；不根据超时推定成功。
2. EXECUTED 表示执行链返回，不表示客户端收到全部流式结果或已完成业务确认。结果读取中断仍需更完整的生命周期追踪。
3. 请求编号尚未端到端贯通 managed executionId、所有 SQL 执行单元与 Doris queryId；不能仅凭此编号自动证明 Doris 提交结果。
4. 非多用户旧路径、账号 DCL 独立路径不获得本批完整审计包装保证。已存在的 UNKNOWN 任务也不会被自动恢复。
5. 对象代次、旧任务与新对象的 CAS 防护、执行后恢复任务的持久化仍未完成。此次没有改动这些存储模型。
6. 不同客户端是否自动重试取决于其配置；39001 和提示只是明确契约，不能强制阻止业务系统自行重试。
