## 已实现

### 1. 账号变更分域

- `AccountChangeImpact` 单独声明操作影响域。
- 保留旧 `epoch` 作为凭据版本，新增 `permission_epoch`，兼容旧库升级。
- GRANT/REVOKE 不再增加凭据版本，原 MySQL 连接可继续使用；操作同步期间仍阻断访问。
- PASSWORD/DROP 继续使旧会话失效。恢复中的凭据任务仍失效旧凭据，避免崩溃窗口绕过。
- 用户返回策略保持独立，不改变认证版本。
- Doris 仍负责执行时的真实权限判断，不以网关权限投影替代。

### 2. 独立物理身份检查模块（受控启用，尚非完整产品闭环）

- `ObjectIdentityProvider` 隔离数据库方言；Doris 实现读取 `information_schema.metadata_name_ids` 的 catalog/database/table ID。
- `ObjectIdentityService` 负责持久化、校验与隔离，不依赖脱敏规则或用户策略。
- 新增 `physical_object_bindings`，主键为网关对象 ID 与代次；新增 `object_identity_enforcement` 记录启用范围。
- 旧库必须先预览、再确认基线；未完成对象任务会阻止确认。预览变化、代次变化、网络失败不能部分提交基线。
- 已启用库：查询前检查物理身份；写入确认/恢复检查目标身份。CTAS 首次确认捕获身份，后续恢复不得按同名猜测。
- 同名替换一经确认，持久化隔离；即使再次扫描、普通审批、重复基线确认，也不能覆盖旧身份。
- 正常改名保留身份；经网关 DROP 后重建采用新代次。
- 普通审批和重新接入增加身份检查，禁止借此隐式接纳替换对象。
- 管理接口：GET `/api/object-identities/{database}/preview`；POST `/api/object-identities/{database}/confirm`，请求体为预览清单。沿用管理员认证。状态冲突返回 409。

## 验证结果

- 管理端完整构建：116 项测试，115 通过、1 跳过、0 失败。
- `ObjectIdentityTest` 9 项：只读预览、过期预览、持久隔离、审批保护、事务回滚、元数据不可用、改名、创建恢复等。
- `object-identity-e2e.cjs`：6 组真实测试通过。独立临时库接入后启用身份检查，覆盖 DROP/同名重建、CTAS 脱敏继承、RENAME、INSERT SELECT、外部同名同结构替换、过期确认拒绝。
- 原隔离测试库含历史未完成任务，基线确认被拒绝；没有清理历史任务或绕过校验。
- `identity-visibility-probe.cjs`：仅持有单表 SELECT_PRIV 的临时 Doris 用户可读取该表物理身份，结果与 root 一致。此结论只针对本次服务器版本及权限组合，不推定所有 Doris 版本一致。
- `account-domains-e2e.cjs`：6 组真实测试通过，包括原连接授权/撤权/再次授权、最后一项授权撤销、直连 Doris 撤权、返回策略切换、密码和删用户。
- `snapshot-regression-e2e.cjs --automatic`：6 组真实回归通过。
- 临时物理测试库和临时用户已删除。隔离管理库保留解除接入后的审计/身份记录，便于复查；未删除业务库表。

## 未完成与明确边界

1. 物理身份检查仍是按库显式启用，未自动覆盖存量库或所有新接入库；目前只提供管理员 API，尚未加入 UI。
2. 外部新表或替换表“作为新来源重新接纳”的代次切换、旧血缘隔离、策略预览与确认闭环尚未实现。严格模式下无身份基线的外部表保持拒绝，不能以普通审批自动放行。
3. 查询前身份检查与外部 DDL 之间仍可能存在竞态；不能宣称与绕过网关的 DDL 具有数据库事务级原子性。首次创建成功与身份捕获之间也存在外部替换窗口。
4. 尚未完成结果返回阶段的身份复核、恢复时全部来源身份复核、大规模元数据检查的性能评估。每次校验当前会建立元数据连接，不能在未压测前全量开启。
5. Doris 外部 catalog、物化视图和不同版本的元数据能力还需单独验证；无法取得身份时不退回按名称放行。
6. LIMIT 参数适配和 Doris 原生语法兼容适配尚未实现。

因此，本阶段是安全校验底座与权限解耦的开发验证，不等于全部整改完成，不应直接作为全量生产升级交付。
