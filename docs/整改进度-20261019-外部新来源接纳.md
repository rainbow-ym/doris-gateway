# 外部新来源接纳：开发与隔离验证

日期：2026-10-19（北京时间）。生产 18080/3308 未更新。

## 本阶段完成范围

只处理“首次发现、没有旧身份/旧血缘/旧策略版本/旧执行记录”的外部新表。
同名替换不是首次接入，本阶段仍拒绝按新表覆盖，不伪造、清除或继承旧血缘。

流程：

1. 已接入的逻辑库完成物理身份基线确认。
2. 绕过网关创建表后，通过现有扫描功能发现表，状态为未纳管。
3. 管理员预览新来源身份，再确认。确认过程中重新读取物理 ID，并检查网关代次与未完成任务；仅持久化身份，不开放查询。
4. 复核字段保护，使用现有“批准并同步”发布该表策略。发布完成后再次检查物理身份，再激活表并更新账号权限投影。
5. 身份确认后若服务中断，表仍未纳管；可继续原审批。审批失败后新表保持未纳管且不可查询，允许人工重试，不重放业务 SQL。异常策略发布仍需沿用原发布恢复流程，不跳过发布隔离。

新增管理员接口：

- GET `/api/object-identities/new-sources/{id}/preview`
- POST `/api/object-identities/new-sources/{id}/confirm`，提交预览中的 `generation_id`、`physicalIdentity`；对象由路径 ID 决定。

中文界面增加：

- 血缘页面“预览物理身份基线”，显示前 100 项和总数，明确提示实际确认全部预览对象及元数据访问成本。
- 未纳管对象“确认新来源身份”，使用现有详情弹窗。
- 身份确认与批准纳管保持分开，不自动打开查询权限。重复确认不重置对象。
