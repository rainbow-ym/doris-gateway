# SM4 逐行加密导出（2026.10.19 row-v2）

三个服务镜像统一使用 sm4-row-v2-20261019。与旧末行版协议不同，必须配套升级，不要混用。默认关闭。

## 返回方式

结果行数不变，在最后新增 VARCHAR(30000) 列 `__gateway_sm4`。一行中所有受保护字段的原值（不是星号值）合并成带列位置、列名/别名、类型的结构，进行一次 SM4-GCM 认证加密。原业务字段继续脱敏。一行一个密文，不是一个字段一个密文，也不是整份结果一个密文。

例如：`证件号码 | 姓名 | __gateway_sm4`，数据为 `110101********1234 | 张* | __GW_SM4_V1__:v1:...`。外层封装前缀沿用 V1，认证载荷 format 为 ROW_V2；不接受旧末行 CSV。

不含保护字段的查询不加列。空的受保护结果仍有新增列元数据，但没有数据行。业务列已使用保留名 __gateway_sm4 时明确报错。

## 页面和接口

管理员登录平台，进入集群 → SM4 加密导出，填写已接入的真实用户名和逻辑库，勾选“启用逐行 SM4 加密”和“允许管理员解密”，保存确认。建议初测最大行数 20、有效期 10 分钟。

启用后同账号同库所有受保护查询都增加密文列，不仅是点击导出时。业务系统必须读取并导出新增列；网关无法强制既有业务页面显示未读取的列。需内网实际验收。

导出带表头、逗号分隔的 UTF-8 CSV，在页面上传，点击“校验并下载明文”。整行连同密文排序、选取部分行均可；列不能调换，不能只移动密文、修改显示值或截断密文。任一行校验失败则整份文件不返回明文。解密后移除密文列，还原业务列。

接口：POST `/api/sm4-export/decrypt`，JSON `{ "csv": "带表头的CSV内容" }`，成功返回 `{ "csv": "还原后的CSV", "filename": "decrypted-rows-...csv", "rowCount": 1 }`。worker 仅本机管理员认证访问；平台使用 `/api/clusters/{集群ID}/relay/api/sm4-export/decrypt`，需要登录会话与 CSRF。不是匿名接口，不应对公网暴露 worker。

解密重新验证回执、有效期、撤销状态、凭据版本、解密开关、来源表身份和当前 Doris 权限。原始值不写入系统库，回执和审计按加密行记录。撤销不能收回已下载明文。

## 限制

- 仅文本、整数、定点数；不支持日期、浮点、二进制结果及 XLSX。最多 255 个业务列加 1 个密文列、1000 行。
- 每个密文最多 30000 字符，一次结果密文总量最多 768 KiB，CSV 最大 1 MiB。协议请求和缓冲也有限额，超限拒绝，不静默截断。
- 固定列数、ORM 映射、显式导出字段名单可能不兼容新增列；需实际业务验收。
- NULL 导出为空；下载 CSV 对公式前缀添加单引号防止执行，不承诺 SQL 类型无损往返。
- 解密者为管理平台管理员，不代表业务系统最终用户。共用数据库账号不能区分业务人员。

## 新装与保留旧部署升级

新装参照 README.md。旧部署不要执行 init、不要覆盖数据目录。校验离线包、docker load，再按照 SAFE-UPGRADE.md 安排维护窗口、stage、验证、accept，三个服务一起更新。

若原部署无 SM4 密钥，启用前执行：

```bash
bash init-sm4-key.sh /实际安装目录/worker-data/sm4-export-keys.properties
```

已有文件保留，不能重新生成覆盖。文件权限 600，安全备份系统库和密钥，不提交 Git。升级保留原账号、连接、策略、血缘。先确认普通脱敏，再启用 SM4；旧末行配置不能代替新增列的业务兼容验收。
